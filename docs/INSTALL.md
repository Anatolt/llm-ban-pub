# Installation

## Docker

Follow the README quick start. `scripts/configure.py` creates `.env` with a
random password and copies `config/agents.example.json`. It never overwrites an
existing file. `.env`, runtime config, data, backups and workspaces are ignored
by Git and excluded from Docker build contexts.

The `data` named volume contains the board, work registry, agent runs, reports
and Telegram outbox. Board and worker share the same SQLite database. There is
no import from the original private LLMBAN, no sample production data and no
dependency on an external memory directory or SSH alias.

The default project is `demo`. Replace it with real cloned repositories before
queuing tasks. The worker image contains Python, Node, Pi, Git and ripgrep.
Project-specific build tools (compilers, package managers, browsers, etc.) must
be added in your own derived worker image. Do not install requirements on the
Docker host just to make them visible inside a container.

For a different provider, pass the environment variable Pi expects to the
worker service using a private Compose override. Never put credentials in argv,
cards, prompts or committed config. OAuth/custom Pi configuration requires a
separate explicitly mounted agent configuration; never mount your full home.

Check startup:

```sh
docker compose ps -a
docker compose logs --tail=100 web worker
```

If a worker says a workspace is absent, correct the map inside
`config/agents.json` and its host mount. If it reports permission denied, check
UID/GID ownership. `LLMBAN_UID` must be nonzero. Never solve permissions by
running the worker as root or making your repositories world-writable.

## Reverse proxy

Terminate TLS with your existing proxy and forward to `127.0.0.1:8080`.
Preserve the `Authorization` header. Set a modest request-body limit (e.g. 1 MB),
restrict access to your team, and rate-limit authentication attempts at the
proxy. This release has one shared instance account, not per-user permissions.

Example Nginx server fragment (inside your TLS vhost):

```nginx
location / {
    client_max_body_size 1m;
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header Authorization $http_authorization;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Use a dedicated domain at `/` with the provided Compose file. For a custom
subpath, a native installation supports `LLMBAN_BASE_PATH=/kanban`; configure
your web server to route that prefix to `public/index.php`. Do not change only
the environment variable without matching routing rules.

## Native Linux/macOS

Requires PHP 8.2+ with PDO SQLite/session, Python 3.11+, and Node 22.19+ only when
using Pi. No pip install is needed. Windows users should use Docker or WSL2;
the worker requires POSIX process groups and file locks.

```sh
python3 scripts/configure.py --native
set -a
. ./.env
set +a
python3 bin/board.py init
php -S 127.0.0.1:8080 -t public public/router.php
```

The PHP built-in server is for local development. Production native deployments
should serve **only `public/`** with Apache or Nginx/PHP-FPM. Give the web user
and worker a dedicated shared data group, set the data directory to mode 2770,
and keep SQLite files writable by both users. Never expose the repository root
as a web document root.

In a separate terminal, export the same environment and run:

```sh
npm install -g --ignore-scripts @earendil-works/pi-coding-agent@1.4.0
python3 bin/worker.py
# Optional, only with Telegram explicitly configured:
python3 bin/telegram_notifier.py
```

Use your process supervisor to run these as an unprivileged dedicated user.
The worker uses `config/agents.json` unless `LLMBAN_CONFIG` is set. Native work
paths and argv paths are generated by `--native` only when no config exists.
If switching from Docker, edit the existing config explicitly; it is preserved.

## Verify an installation

1. Unauthenticated `/` and `/api/cards` return 401.
2. After login, create/edit/move a test card and confirm it persists after a
   web-service restart.
3. Configure an isolated test repository, then move a small task to `llm plan`.
   Review `man plan` before moving it to `llm todo`.
4. Review the diff, test report and `man test` result. Provider credentials and
   billing are yours; the offline test suite does not validate a live model.
5. If enabled, confirm Telegram delivery to your own configured chat.
